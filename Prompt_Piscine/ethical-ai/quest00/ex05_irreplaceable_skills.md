# Self-Assessment and Improvement Plan

1. Problem Decomposition

Description: Breaking complex problems into clear, manageable parts
- Rating: 3/5

Reasoning:
I can usually identify the main components of a problem, but I often refine the breakdown while coding instead of fully structuring it beforehand. This sometimes leads to rework.

Improvement Plan:
Before writing any code, I will write a short outline of the major steps or components required to solve the problem, even for small tasks.


2. Systems Thinking

Description: Understanding how components interact and how changes affect the whole system.
- Rating: 2/5

Reasoning:
I tend to focus on making individual pieces work correctly without fully considering how they connect, scale, or break when requirements change. I recognize this as a weakness in anticipating side effects.

Improvement Plan:
I will consciously practice thinking beyond individual functions by mapping inputs, outputs, and dependencies for any non-trivial task.


3. Critical Evaluation

Description: Knowing when code is incorrect, inefficient, or misleading
- Rating: 3/5

Reasoning:
I question results when they look wrong and can spot obvious inefficiencies, but I sometimes accept solutions that “work” without deeply examining edge cases or long-term implications.

Improvement Plan:
After completing a solution, I will review it specifically by looking for assumptions, edge cases, and unnecessary complexity.


4. Debugging Mindset

Description: Systematically investigating unexpected behavior
- Rating: 3/5

Reasoning:
I’m comfortable experimenting and trying fixes, but I don’t always isolate variables methodically, which can slow down root-cause discovery.

Improvement Plan:
I will practice reducing bugs to the smallest reproducible example before attempting fixes.


5. Conceptual Understanding

Description: Understanding why something works, not just how to use it
- Rating: 2.5/5

Reasoning:
I understand core concepts at a functional level, but I don’t always trace them back to first principles or underlying mechanisms.

Improvement Plan:
For each new concept I use, I will write a brief explanation of the problem it was designed to solve and the trade-offs involved.


- Lowest-Rated Skill: Systems Thinking (2/5)

## Three Actions This Week (No AI Use)

1. Pre-code System Sketching:
Each day, I will take one medium programming problem and draw a simple diagram showing data flow, key components, and dependencies before writing any code.


2. Change-Impact Reflection:
After completing any small project or exercise, I will answer on paper:
“If I'll add one major feature tomorrow, which parts of this system would need to change, and why?”


3. Conceptual System Study:
I will watch one short, non-tutorial video this week explaining a system (e.g., how browsers work, how Git stores data, or how HTTP works) and summarize how the components depend on each other. In fact, I have downloaded "The Art Of Thinking In System" by Steven	Schuster.
